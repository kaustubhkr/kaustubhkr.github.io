01 / Implementation

Capture and inference lifecycle

  • Implemented separate paths for AudioQueue dictation and ScreenCaptureKit system-audio plus microphone capture.
  • Used 20 ms PCM callbacks and rolling lossless 16 kHz mono audio files for dictation.
  • Built provisional phrase decoding followed by an independent quality pass over the original audio.
02 / Implementation

Resource and failure handling

  • Bound the number of loaded model workers and serialized GPU inference requests.
  • Kept microphone startup independent of remote-backend discovery and model loading.
  • Preserved provisional text when finalisation fails, with explicit microphone-open, first-audio, first-text and stop-to-final timings.
03 / Implementation

Personal memory

  • Built local multilingual transcription and speaker-aware processing around existing speech models.
  • Added SQLite-backed memory, retrieval, correction handling and optional backend-routing contracts.
  • Made capture, transcription, storage and action boundaries visible in the native application.
Engineering note

Latency is a sequence of boundaries.

The time before useful text appears includes opening the input device, receiving the first real samples, accumulating context and scheduling inference. I separated those stages so a slow device open does not disappear inside a single transcription-time number.

Project context

Actively developed native application. Hardware-dependent capture and cross-application actions have their own device-validation requirements.
