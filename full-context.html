Research direction / Second company in stealth # Make machine work transferable and verifiable. Industry 6.0 is my long-term ambition. The research problem is concrete: preserve a task’s intended outcome when its machine, fixture or operating conditions change. Working representation task = outcome + constraints + preconditions + actions + acceptance A command acknowledgement does not establish that the physical outcome occurred. Completion needs observations tied to the task’s acceptance conditions. 01 ### Bind intent to a real machine. Represent target state, units, geometry and tolerances; bind process steps to available resources. Evaluate mapping effort and task completion after a machine or fixture change. 02 ### Learn where prediction changes action. Use learned dynamics for action selection and recovery. Compare against classical control under the same constraints: rollout error, task success, tail latency and failure cases. 03 ### Recover with evidence. Invalidate dependent steps after physical state changes. Test interrupted motion, stale observations and missing evidence; measure detection and recovery, and withhold unsupported verdicts. These are research questions and evaluation criteria. The engineering case studies ↗ (https://kaustubhkr.github.io/work.html) document work built so far. PPO / On-policy #### Clipped probability-ratio objective Gaussian policy, clipped surrogate, entropy regularisation, minibatch epochs, separate value regression and gradient-norm clipping. TRPO / Trust region #### Curvature without a dense Hessian (H KL + λI) Δθ = g Hessian–vector products + conjugate gradients - 01 #### Differentiate g = ∇θ L(θ) Flatten autograd derivatives of the policy-ratio surrogate. - 02 #### Solve v → Hₖₗv + λv Differentiate the gradient–vector product; solve iteratively with residual-based termination. - 03 #### Scale ½ ΔθᵀHΔθ ≤ δ Scale the candidate step using the KL curvature estimate. - 04 #### Accept / revert KL budget ∧ improvement Backtrack until the surrogate improves inside the trust region; restore the old parameters if no candidate passes. The industrial design carries a trained policy into an inference-only runtime with declared shapes, normalisation, action bounds, timing and fallback responsibilities. - 01 #### Train Python / JAX → frozen parameters Version the experiment, data assumptions and policy checkpoint. - 02 #### Package model.onnx + metadata.json Bind the exported graph to the observation/action contract and model hash. - 03 #### Execute acquire → normalise → infer A fixed-tick C++20 runtime with preallocated working buffers is the target execution design. - 04 #### Constrain clamp → rate / jerk → action Monitor validity and timing; signal the classical-control path when takeover is required. #### What travels with the model abi_version · dimensions Interface version, obs_dim and act_dim define compatibility. obs_norm · preprocess The runtime receives the same normalisation and preprocessing used in training. act_bounds · tick_hz Action limits and the expected control period are explicit. training_commit · onnx_sha256 The binary resolves to a particular training revision and content hash. kpi_ref · license Evaluation context and usage terms travel with the artifact. #### How the learned policy gets control authority Shadow Residual Primary Cooperative ### Shadow u = u classical The learned policy observes and logs counterfactual actions. The classical controller retains command authority. Compare proposed actions with the actual execution before handover. ### Residual u = guard(u classical + Δu policy ) The learned policy contributes a bounded correction over the classical controller. The combined command passes through the actuator envelope. Bound the residual and define the trigger for returning to the classical controller. ### Primary u = guard(u policy ) The learned policy supplies the main action within the declared execution envelope. Deadline, novelty and input monitors can request fallback.
