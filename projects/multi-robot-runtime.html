01 / Implementation

Localisation and frame ownership

  • Configured one shared map with three separately namespaced AMCL instances and per-robot initial-pose bootstrapping.
  • Merged front and rear laser scans for the applicable robot and provided configurable sensor-frame alignment.
  • Implemented TF chain validation and publisher-conflict tracking, including expiry of stale sources after restarts.
  • Added world-to-map calibration tools so initial poses and geometry share a declared reference frame.
02 / Implementation

Authority over motion

  • Separated raw motion intent from the final command publisher in the evidence-mode runtime.
  • Implemented deterministic command-gate logic for stale stop, mode, interlock and warning inputs.
  • Represented active stops, deliberate-restart requirements, charger contacts, load state, doors, portals and prestart warnings as explicit inputs to arbitration.
03 / Implementation

Repeatable physical-system experiments

  • Built mission and fork-adapter components, deterministic scenario models and a scenario runner.
  • Recorded rosbag2 episodes with artifact bundles and declared signal contracts.
  • Checked topics, frames, publisher ownership, timestamps and freshness at the interface between simulation and the runtime.
Engineering note

A coordinate transform also has an owner.

Two publishers can produce individually plausible transforms while making the combined system inconsistent. The runtime tracks the active sources for monitored frame pairs, expires stale publishers, and reports competing authority. The same ownership discipline applies to final velocity commands.

Project context

A simulation-development runtime. Protective-device and PLC models here are development components, not certified machine-safety functions.
